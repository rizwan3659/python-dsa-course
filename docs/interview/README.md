# Interview preparation

The goal is to **recognise patterns**, not to memorise answers. Everything here links back to problems in the course.

| Guide | Use it for |
|---|---|
| [Top 100 roadmap](top-100.md) | What to practise, in which order, in three tracks (beginner, intermediate, advanced) |
| [Pattern guide](patterns.md) | Recognising which technique a new problem needs, with a template for each |
| [Communicating a solution](communication.md) | What to say, and when, from reading the problem to testing your code |
| [Common Python mistakes](python-mistakes.md) | The bugs interviewers see most often in Python solutions |
| [Mock interviews](mock-interviews.md) | Scripts for practising with a partner, plus a scoring rubric |

## Practice modes in the course

| Mode | Where | When |
|---|---|---|
| Learn the pattern | Browser: topic lessons; locally: `python dsa.py list <topic>` | First time you meet a pattern |
| Pattern drill | Topic 23 → "Pattern recognition drill" quiz | Daily, 10 minutes |
| Complexity drill | Any topic's Review tab quiz (complexity questions) and Topic 2 | Until you answer in under 30 seconds |
| Timed practice | Interview page: 20 / 35 / 45-minute rounds with no hints | 2–3 times a week once a track is half done |
| Spaced revision | Revision page (wrong answers return after 1, 2, 4, 8 days) | Every day |
| Mock interview | With a partner, using [mock-interviews.md](mock-interviews.md) | Weekly in the last month |

## A weekly rhythm

- **Mon–Thu:** 3–4 roadmap problems a day from the current group. Write the pattern and complexity as a comment before coding.
- **Fri:** one timed interview round, then redo any problem you failed this week from a blank file.
- **Sat:** a mock interview with a partner (switch roles).
- **Sun:** revision queue only.
